How Our System Works

The core of this project is a Random Forest classifier — an ensemble machine learning model made up of 200 decision trees — built with scikit-learn. It was trained on the PhiUSIIL Phishing URL Dataset, expanded with real domains from the Tranco top-sites ranking and additional synthetically generated legitimate URL patterns, to correct formatting bias found during development. The final model was validated on held-out test data with 98.93% accuracy.

Every prediction is generated locally, in well under a second, purely from the text of the URL — 23 structural features are extracted (length, character composition, HTTPS usage, subdomain depth, entropy, and more) and passed to the trained model.

This Tool

Frequently Asked Questions

How do I check if a link is safe?

Paste the full URL or domain into the checker above and click Check URL. The analysis runs locally and returns a trust score and a heuristic signal breakdown within a second.

Is a clean result a guarantee the site is safe?

No. This tool analyzes URL structure only — it does not check live threat databases or fetch the destination page. Treat it as one useful signal, not a final answer.

What are the signs of a phishing URL?

HTTP instead of HTTPS, a raw IP address as the host, deep or misleading subdomains, URL shorteners, risky top-level domains (.xyz, .tk, .top), and suspicious keywords like "verify," "secure," or "login" appearing where they shouldn't.

What is a phishing website?

A phishing website is a fraudulent site designed to imitate a legitimate one — often a bank, email provider, or well-known brand — in order to trick visitors into entering credentials, financial details, or personal information.

What happens if I click a phishing link accidentally?

Simply clicking a link is usually not enough to compromise you, but the destination page may try to collect credentials you enter, or in some cases exploit browser vulnerabilities to install malware. The real risk begins if you enter information or download/run a file.

What should I do if I've already clicked a phishing link?

Do not enter any information on the page. If you already entered a password, change it immediately on the real site and on any other account reusing that password. Run a malware scan if you downloaded or opened anything. Monitor financial accounts if payment details were entered, and report the link to your email provider or IT/security team.

How is this different from other phishing checkers?

Tools like commercial phishing checkers primarily look up a URL against live threat-intelligence databases and follow redirect chains. This project instead predicts from the URL's structure alone, using a locally trained machine learning model — no external services, works offline, but can be less certain on structurally ambiguous URLs. See "How Our System Works" above for a full comparison.

Where does this system fail?

The model can struggle with URLs that are structurally ambiguous — for example, a personal blog on a free hosting platform can look identical, in URL structure alone, to a phishing site hosted the same way. It can also be less confident on unusual-but-legitimate patterns not well represented in training data, such as certain numeric IDs or uncommon path structures. These are documented, known limitations of any lexical-only (text-based) detection approach.

What upgrades are planned for the future?

Planned improvements include incorporating domain age (via RDAP lookup), optional integration with public threat-intelligence feeds for a hybrid verdict, browser extension support, and continued dataset expansion to reduce remaining false positives on unusual-but-legitimate URL patterns.
